# CLAUDE.md - AI Team Configuration for insight-mode

## Project Overview

**insight-mode** is an AI-powered daily insight aggregator that fetches AI/ML research papers from arXiv, analyzes them using LLMs to extract business opportunities and innovations, and delivers daily summaries via email.

### Tech Stack

| Category | Technology |
|----------|------------|
| **Language** | Python 3.10+ (modern type hints, dataclasses) |
| **Storage** | SQLite (RawStore, InsightStore) |
| **LLM** | OpenAI-compatible API (GPT-4, Qwen, etc.) |
| **Data Sources** | arXiv API (cs.AI, cs.LG, cs.CL) |
| **Delivery** | SMTP Email (pluggable architecture) |
| **Config** | YAML (config.yaml) + dotenv (.env) |
| **Testing** | pytest-style unit tests |

### Architecture

```
Pipeline: Fetch → Store → Analyze → Deliver

┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Fetcher   │───▶│  RawStore   │───▶│  Analyzer   │───▶│ InsightStore│
│  (arXiv)    │    │  (SQLite)   │    │   (LLM)     │    │  (SQLite)   │
└─────────────┘    └─────────────┘    └─────────────┘    └──────┬──────┘
                                                                │
                                                                ▼
                                                       ┌─────────────┐
                                                       │   Delivery  │
                                                       │   (Email)   │
                                                       └─────────────┘
```

### Conventions and Patterns Used in This Codebase

#### Code Style
- **Python 3.10+** with modern type hints (union types with `|`, generic types)
- **Dataclasses** for data models (`RawItem`, `Insight`)
- **Type annotations** required for function signatures
- **Google-style docstrings** for modules and functions

#### Architecture Patterns
- **Pipeline Pattern**: Fetch → Store → Analyze → Deliver
- **Plugin Architecture**: Delivery plugins implement `DeliveryPlugin` interface
- **Repository Pattern**: `RawStore`, `InsightStore` abstract database operations
- **Adapter Pattern**: Source adapters (arXiv) normalize external data

#### Error Handling
- Explicit `try/except` blocks with logging
- Graceful degradation (e.g., fetch failures don't crash the pipeline)
- Type-safe null handling with `| None` unions

#### Configuration
- **YAML** for non-sensitive configuration (`config.yaml`)
- **Environment variables** for secrets (`.env` file)
- Hierarchical config access with safe defaults

#### Testing
- Unit tests in `tests/` directory
- Mock external dependencies (LLM API, SMTP)
- SQLite in-memory or temp databases for tests
